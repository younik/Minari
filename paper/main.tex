\begin{abstract}
Offline reinforcement learning (RL) depends on shared datasets, but sharing them is still hard. Each benchmark ships its own format, documentation is thin, and most datasets cannot be regenerated once the environment code moves on. We introduce \emph{Minari}, an open-source Python library for creating, sharing, and loading RL datasets. Its API follows Gymnasium, so recording a dataset means wrapping an environment and stepping through it as usual. From there, users can attach metadata, filter, combine, and shuffle datasets, and publish or download them with one command through the HuggingFace Hub. Every dataset stores the environment specification, seeds, applied wrappers, and pinned package requirements needed to rebuild the environment and regenerate the data.
TorchRL, AgileRL, and d3rlpy already load Minari datasets natively, so switching datasets in those libraries takes one line of code. Minari also hosts \numdatasets reproducible datasets (\numtrajectories trajectories, \numsteps steps) covering robotic locomotion and manipulation, maze and grid navigation, language-conditioned instruction following, Atari, and web navigation, including a full regeneration of D4RL with public generation scripts. We report baseline scores for six offline RL algorithms on the regenerated D4RL and MuJoCo datasets.
\end{abstract}

\section{Introduction}

Agents that learn from their own interaction data are an increasingly central part of AI research \cite{experience-era}. That data, the record of what an agent saw, did, and got in return, is expensive to collect and useful well beyond the project that produced it. Yet very little of it is shared in a form that others can reuse.

Three problems get in the way. First, there is no common format. Each benchmark defines its own layout for observations, actions, and episode boundaries, so a loader written for one rarely works on another. Second, released datasets are usually frozen snapshots: the environment version, seeds, and wrappers used to generate them are not recorded, and once the simulator changes the data can no longer be regenerated or evaluated under matching conditions. D4RL \cite{d4rl}, the most widely used offline RL benchmark, is a case in point; its datasets depend on deprecated versions of MuJoCo and Gym. Third, combining data from several sources means reconciling spaces, metadata, and conventions by hand.

Minari is our answer to these problems. It is an open-source library that defines a dataset format for sequential decision-making and the tools to create, share, and load data in that format. The API mirrors Gym and Gymnasium \cite{gym, gymnasium}, which most RL practitioners already use daily: Figure~\ref{fig:code} shows that recording a dataset takes a wrapper and one function call, and loading one takes a single line. Datasets are versioned and hosted on the HuggingFace Hub\footnote{\url{https://huggingface.co}}, and can be listed, downloaded, inspected, and combined from the command line or from Python. Section~\ref{sec:library_features} describes these features in detail.

We want Minari to do for RL datasets what Gymnasium did for environments: give the community one interface, so that a new dataset is usable by every compatible training library the day it is published.

\paragraph{Contributions.} This paper makes the following contributions:

\begin{itemize}
    \item \textbf{A dataset format and library.} An environment-agnostic format for trajectory data with machine-readable metadata and a fixed naming scheme, implemented in a pip-installable library with a Python API and a command-line interface (Sect.~\ref{sec:library_features}).
    \item \textbf{Reproducibility by construction.} Each dataset records the environment specification, generation seeds, applied wrappers, and pinned package requirements, so the generating environment can be rebuilt and the data regenerated. Earlier offline RL benchmarks store none of this (Sect.~\ref{sec:repro}).
    \item \textbf{A dataset collection.} \numdatasets datasets (\numtrajectories trajectories, \numsteps steps) in six collections, each documented and released with its generation script. This includes a regeneration of D4RL on maintained versions of MuJoCo and Gymnasium (Sect.~\ref{sec:datasets}).
    \item \textbf{Baselines.} Scores for six offline RL algorithms, run with CORL~\cite{corl}, on the regenerated D4RL and MuJoCo datasets (Sect.~\ref{sec:benchmarks}).
\end{itemize}

Minari is maintained by the Farama Foundation alongside Gymnasium, and TorchRL, AgileRL, and d3rlpy already load its datasets natively (Sect.~\ref{sec:integrations}).

\paragraph{RLDS} RLDS \cite{rlds} defines a schema for RL trajectories and a set of operations on them, built on TensorFlow Datasets. Minari's episode-level schema owes a lot to it. The catch is the dependency: using RLDS means bringing in TensorFlow, which most current RL code bases, written in PyTorch or JAX, do not otherwise need.

\paragraph{D4RL} D4RL \cite{d4rl} made offline RL a benchmarkable problem, and most offline RL papers since report results on it. But its datasets were generated with specific, now-unmaintained versions of Gym and mujoco-py, and the generation settings were not stored with the data. As those dependencies age, the datasets become hard to load and impossible to regenerate exactly. D4RL also offers no way for users to create datasets of their own in the same format. Minari regenerates the D4RL tasks on maintained software (Sect.~\ref{sec:d4rl}) and gives users the same tools we used to do it.

\paragraph{RL Unplugged} RL Unplugged \cite{rlunplugged} provides offline datasets for the DeepMind Control Suite \cite{deepmindcontrolsuite}, Atari, and other domains, with more emphasis on hard exploration settings than D4RL. Like D4RL, it is a fixed release. It has no tooling for creating compatible datasets and records no information for regenerating the data.

\paragraph{LeRobot} LeRobot \cite{lerobot} provides models, datasets, and tools for real-world robot learning in PyTorch, with datasets hosted on the HuggingFace Hub. Its format is built around robot data, such as multi-camera video streams and joint states. Minari targets the general case: any Gymnasium space, any environment, simulated or not.

\paragraph{HuggingFace Hub} The Hub hosts most publicly released models and datasets in machine learning and handles versioning, documentation, and access control. It has no notion of RL episodes, spaces, or environments. Minari uses the Hub as its storage backend and adds that structure on top.

\section{Library integrations}
\label{sec:integrations}
Three offline RL libraries load Minari datasets natively, so users can train on any Minari dataset without writing a data loader.

\paragraph{TorchRL} TorchRL \cite{torchrl} is the PyTorch project's RL library, built from modular components for environments, replay buffers, losses, and agents. Minari datasets load directly into its replay buffers.

\paragraph{AgileRL}
AgileRL \cite{agilerl} uses evolutionary hyperparameter optimization and population-based training to tune agent architectures and hyperparameters during training, with the aim of reducing the tuning burden for practitioners.

\paragraph{d3rlpy}
d3rlpy \cite{d3rlpy} is a PyTorch library of offline RL algorithms, including CQL \cite{CQL}, BCQ \cite{BCQ}, and TD3+BC \cite{TD3+BC}, with a short, scikit-learn-style API.


\section{Library features}
\label{sec:library_features}

\subsection{Dataset standards}
Every Minari dataset has an identifier of the form
\begin{verbatim}
    namespace/environment/dataset_name-v(version)
\end{verbatim}
where \verb|namespace| groups related datasets, \verb|environment| names the environment that produced the data, \verb|dataset_name| describes the content, and the version number tracks revisions. Only the dataset name is mandatory. A dataset of human demonstrations on \textit{AdroitHandDoor} could be called \verb|door/human-v0|, or \verb|D4RL/door/human-v0| inside the D4RL namespace. The convention follows Gymnasium environment IDs on purpose, so the identifier alone tells a user what the data is and which revision they have.

Metadata is stored at two levels. Dataset metadata (Appendix~\ref{app:metadata}) records the number of episodes and steps, the observation and action spaces, the environment specification when one exists, a link to the generating code, authors, the algorithm that produced the data, and the pip requirements of the environment. Episode metadata holds reward statistics (minimum, maximum, mean, standard deviation, and sum), which makes it cheap to filter episodes, for example to keep the top 10\% by return for BC-10\%.

The data itself is a sequence of episodes. Each episode holds observations, actions, rewards, termination and truncation flags, and optional info dictionaries. Observations and actions can be any Gymnasium space, including nested \verb|Dict| and \verb|Tuple| spaces and \verb|Text| (Appendix~\ref{app:spaces}), and the episode structure stays the same regardless. Terminations and truncations are kept separate because offline RL algorithms need the distinction: bootstrapping from a time-limit truncation as if it were a terminal state biases value estimates.

Storage is pluggable behind the same API. HDF5 is the default and suits small and medium datasets, while the Arrow/Parquet backend is meant for large datasets and distributed training.

Minari is a pure Python package installable with \verb|pip install minari|. It covers four tasks: creating, loading, manipulating, and sharing datasets.

\paragraph{Creating datasets.} There are two ways to create a dataset. The \verb|DataCollector| wrapper records every step of a Gymnasium environment while the agent runs, with no other changes to the training or rollout code (Fig.~\ref{fig:code}, top). For data that does not come from a Gymnasium environment, such as logs from another simulator, a real robot, or an existing dataset in another format, \verb|create_dataset_from_buffers()| takes a list of episode buffers and writes them in the Minari format. For pixel observations, Minari can optionally JPEG-encode frames, which shrinks on-disk and download size for datasets such as Atari.

\paragraph{Loading and manipulating datasets.} Loaded datasets support episode sampling, iteration, filtering by any episode-level predicate, and shuffling. Several datasets with compatible spaces can be combined into one.

\paragraph{Sharing datasets.} \verb|minari upload| publishes a dataset to the HuggingFace Hub and \verb|minari download| fetches it, along with its metadata, so another group can reproduce or extend an experiment from the dataset ID alone. One-off operations like these are also available from the command line without writing Python (Table~\ref{tab:cli}).

\subsection{Improving reproducibility in Offline RL}
\label{sec:repro}

RL results are notoriously hard to reproduce \cite{hendersonDeepReinforcementLearning2019}. Offline RL adds a failure mode of its own: a policy is trained on data from one environment and evaluated in another that is supposed to be identical but is not. A changed time limit, a missing wrapper, or a different simulator version is enough to make scores incomparable, and nothing in a bare array of transitions reveals the mismatch. Minari stores three things to prevent it.

\paragraph{Environment and wrappers.} \pythoninline{dataset.recover_environment()} rebuilds the environment that generated the data from its stored specification, including any wrappers that changed its behavior. Evaluation therefore runs on the same environment as data collection by default, not on whatever the current release of the environment happens to be. When the evaluation task should differ from the collection task, for example a goal-conditioned dataset collected with random goals but evaluated on a fixed one, the dataset can also store a separate evaluation environment, returned by \pythoninline{recover_environment(eval_env=True)}.

\paragraph{Seeds.} When the user does not pass a seed to \verb|reset()|, the \verb|DataCollector| draws one and stores it with the episode. Rerunning the same policy (with its own randomness seeded) from the stored seeds regenerates the same episodes.

\paragraph{Software versions.} Physics simulators such as MuJoCo~\cite{mujoco} integrate rigid-body dynamics numerically, so the same policy can produce different trajectories under different simulator versions. Dataset creators can pin pip requirements when creating a dataset, and Minari checks the installed packages against them when the environment is recovered.

D4RL \cite{d4rl} is still the default offline RL benchmark, but its datasets were generated with mujoco-py and versions of Gym that are no longer maintained. \begin{itemize}
    \item \textbf{Ant Maze} (6 datasets). An 8-DoF quadruped follows waypoints from a Q-value iteration planner through mazes of three sizes, with a success rate above 80\%.
    \item \textbf{Point Maze} (8 datasets). A force-actuated ball moves to random goals, driven by a Q-value iteration planner and a PD controller, in 4 mazes with sparse and dense rewards.
    \item \textbf{Adroit} (12 datasets). A 24-DoF simulated hand performs four dexterous tasks from \citet{d4rl-pen}: rotating a pen to a target orientation, opening a door, hammering a nail, and relocating a ball. The target is four subtasks: open the microwave, move the kettle, flip the light switch, and slide open the cabinet. Following D4RL, \textit{complete} contains all four in sequence, \textit{mixed} completes them alongside other subtasks, and \textit{partial} never completes all four.
    \item \textbf{Minigrid Four Rooms} (2 datasets). A grid agent navigates to a goal in the Minigrid \cite{minigrid} four-rooms layout, under a random policy and an optimal value-iteration policy.
\end{itemize}

BabyAI \cite{babyai} is a set of grid-world tasks for grounded language learning. In each episode the agent receives a natural-language instruction, such as ``put the red ball next to the blue box'', and must carry it out from partial observations. Tasks range from going to a single object to long instructions that chain several subgoals.

Trajectories come from the BabyAI bot, a deterministic expert that solves every level, and each dataset holds 1,000 episodes. Because the instruction is part of the observation (a \verb|Text| space inside a \verb|Dict|), these datasets also exercise Minari's support for structured, non-numeric observations.

\subsection{MetaWorld}
MetaWorld \cite{metaworld} has 50 manipulation tasks for a simulated Sawyer arm, built for multi-task and meta-RL: reaching, pushing, pick-and-place, tool use, opening doors and drawers, pressing buttons, and more. We recorded 50 episodes per task with the scripted expert policies that ship with MetaWorld, which solve nearly every episode. Observations are the full state: hand position, gripper opening, object poses, and goal position. The Adroit datasets offer few tasks with a high-dimensional hand; MetaWorld offers many tasks with a simple gripper and binary success signals, which suits multi-task offline RL and studies of transfer between tasks.


\subsection{WebAgents}
\label{sec:webagents}
We converted WebLINX \cite{weblinx} to the Minari format. It contains 969 successful demonstrations of web navigation tasks, about 24K interaction steps in total, covering form filling, information lookup, and multi-step workflows on real websites. Observations and actions are text and there is no reward. We include it to show that the format is not limited to simulated control: any sequential decision-making data that fits Gymnasium spaces fits in Minari, including data for training language-model agents.


\section{Benchmarks}
\label{sec:benchmarks}

Minari is infrastructure, and benchmarking algorithms is better left to the training libraries built on it (Sect.~\ref{sec:integrations}). Still, a regenerated dataset is only useful if standard algorithms learn from it, so we checked. We trained six offline RL algorithms, BC, BC-10\%, TD3+BC~\cite{TD3+BC}, AWAC, CQL~\cite{CQL}, and IQL, on the regenerated D4RL datasets and on the MuJoCo collection, using the CORL~\cite{corl} implementations and their tuned hyperparameters unchanged. Tables~\ref{tab:benchmarks_d4rl} and~\ref{tab:benchmarks_mujoco} report normalized scores.

We report the best checkpoint over training, not the last. Off-policy actor-critic methods, TD3+BC, AWAC, and CQL in particular, can diverge late in training on narrow datasets, and the final checkpoint then understates what the method reached. CORL reports both for the same reason~\cite{corl}. Best-checkpoint scores are optimistic, so they should be compared with CORL's best-checkpoint numbers and not with last-checkpoint results from the original papers.

\paragraph{What the results show.} The regenerated D4RL datasets keep the difficulty structure of the originals. Expert Adroit data is easy for imitation-style methods (BC, AWAC, and IQL all exceed 100 on every expert dataset), while the human and cloned datasets for \textit{door}, \textit{hammer}, and \textit{relocate} stay hard, with no method above 27.6. IQL is the most consistent method across both tables and lands close to CORL's published scores where a direct comparison exists (87.7 vs.\ 87.5 on \textit{antmaze/umaze}, 106.1 vs.\ 106.7 on \textit{door/expert}). Two departures from published results are worth stating plainly. First, BC and AWAC score higher on the regenerated Ant Maze datasets than on the originals, especially on the large mazes. The regenerated data comes from a different maze implementation and planner rollouts, so exact agreement is not expected, but users comparing against older Ant Maze numbers should be aware of the gap. Second, CQL trails the other methods on Ant Maze and collapses on \textit{hammer} and \textit{relocate}, and TD3+BC fails on \textit{door} and \textit{relocate}. CQL's Ant Maze results are known to be hard to reproduce, and in CORL's configuration it is the only one of the six methods trained without state normalization. We report CORL's settings as-is and have not tuned them for the new datasets.

On the MuJoCo collection (Table~\ref{tab:benchmarks_mujoco}), all methods recover most of the expert's return on \textsc{Hopper} and \textsc{Walker2d}, and the datasets separate methods mainly at the expert tier: TD3+BC and CQL lose ground on \textit{halfcheetah/expert}, and AWAC falls to 29.4 on \textit{walker2d/expert}.

These numbers are sanity checks and a starting point, not a leaderboard. The point is that the datasets work with a widely used training library without modification, and that anyone can now rerun these experiments on data they can also regenerate.

\section{Maintenance, hosting, and licensing}
\label{sec:maintenance}
Minari is maintained by the Farama Foundation, the non-profit that also maintains Gymnasium and PettingZoo, which gives the project support beyond the lifespan of a single research grant. The library is MIT-licensed, distributed on PyPI, and developed in the open on GitHub. Datasets are versioned and hosted on the HuggingFace Hub, which provides free, persistent public access, and their generation scripts live in a separate public repository so each dataset can be regenerated from scratch. Converted third-party datasets such as WebLINX keep their original licenses, and authorship is recorded in each dataset's metadata.

\section{Conclusion}
Minari gives offline RL what Gymnasium gave online RL: one interface that datasets and training code can both target. A dataset recorded with a Gymnasium wrapper today can be published with one command, loaded by TorchRL, AgileRL, or d3rlpy with one line, and rebuilt years later from the environment specification, seeds, and package versions it stores. The \numdatasets datasets we host (\numtrajectories trajectories, \numsteps steps) include a regenerated D4RL that runs on maintained software, along with collections for MuJoCo, BabyAI, Atari, MetaWorld, and web navigation.

Minari has limits. It stores data as episodes and reads it in batches of episodes, which fits poorly with lifelong or open-ended tasks that have no clear episode boundaries. Its general-purpose storage can also be slower than a data loader hand-tuned for one training pipeline. And reproducibility is only as good as what the dataset creator records: Minari can store seeds and pinned requirements, but it cannot make a nondeterministic simulator deterministic.

The collection is meant to grow through contributions. Any group that records data with Minari can publish it on the Hub, and every compatible training library can use it right away.

\section{Episode data structure}

A loaded dataset is a \pythoninline{MinariDataset}, which supports iterating over and sampling episodes. Each episode is returned as an \pythoninline{EpisodeData} object. For example, the following loads \pythoninline{D4RL/door/human-v2} and samples 10 episodes at random:

\begin{python}
import minari
dataset = minari.load_dataset("D4RL/door/human-v2", download=True)
sampled_episodes = dataset.sample_episodes(10)
\end{python}

\pythoninline{sampled_episodes} is a list of 10 \pythoninline{EpisodeData} objects with the following fields:

\begin{table}[H]
    \centering
    \begin{tabular}{lll}
    \toprule
        Field & Type & Description \\ \midrule
        \pythoninline{id} & \pythoninline{int} & ID of the episode. \\
        \pythoninline{observations} & \pythoninline{np.ndarray}, \pythoninline{list}, \pythoninline{tuple}, \pythoninline{dict} & Stacked observations for each step. \\
        \pythoninline{actions} & \pythoninline{np.ndarray}, \pythoninline{list}, \pythoninline{tuple}, \pythoninline{dict} & Stacked actions for each step. \\
        \pythoninline{rewards} & \pythoninline{np.ndarray} & Rewards for each step. \\
        \pythoninline{terminations} & \pythoninline{np.ndarray} & Terminations for each step. \\
        \pythoninline{truncations} & \pythoninline{np.ndarray} & Truncations for each step. \\
        \pythoninline{infos} & \pythoninline{dict} & Additional information returned by the environment \\ \bottomrule

\end{table}

The types of \pythoninline{observations} and \pythoninline{actions} depend on the corresponding spaces.
